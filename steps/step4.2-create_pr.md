# Step 4.2：提交PR

本批`adapt-plan`中的全部适配任务完成，且主agent已收齐开发与验证材料后，才执行本步。存在未完成项或验证阻塞时，留在Step 4处理。

1. **核对成果。** 汇总各subagent的代码改动、任务结果及实际验证报告，确认当前分支为本次`development-branch`。
2. **commit并push。** 由主agent提交本批代码改动，将开发分支推送到fork远端`origin`，确认推送成功后再提PR。
3. **提交PR。** 从该fork分支向主仓`upstream`的`master`提交PR，关联Step 4.1的issue，写明改动内容和真实验证结果。本批已有PR时更新原PR，不重复创建。
4. **交给Step 5跟踪。** 将PR链接、提交号和推送结果保存在本次run-id材料，连同issue链接交给Step 5。

提交、推送或创建PR失败时，保留当前分支和进度，先恢复本批发布，不开始下一批任务。重试时复用已完成的提交及已有issue、PR。

本批开发完成、代码已推送且PR提交成功后，首次发布完成；后续评审和依赖分支同步由Step 5负责。
