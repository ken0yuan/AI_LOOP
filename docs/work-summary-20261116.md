## 5. 支持单 API、多 API 与本轮最新新增 API 输入

按照用户先修改的流程文字，对齐初始化、任务选择脚本及说明：

- `--api` 接收一个或多个名称，不设固定数量上限；逐个校验，描述保留整组名称，运行目录以第一个 API 命名。
- `--new-apis` 使用 `adapt-new-<日期>`，描述固定为 `New API needs adaptation`。
- 准备日志将原 `api` 字符串调整为 `apis` 数组，并增加 `new_apis` 标记。
- 名称校验允许显式短名称；多个名称中后续未登记的反引号名称会报缺项，不再静默漏掉。
- 最新模式只读取本次运行实际新增入库的名称；取消一度误加的“首次出现版本相同就入选”逻辑，避免每天重复下发同版本旧条目。
- `api-refresh/new-apis.json` 继续作为字段补全名单；另存 `api-refresh/added-apis.json`，记录本轮真正插入的新行。内部转对外及恢复上线不计为实际插入的新行。
- 同一运行重跑保留本轮新增名单；新运行没有新增时保存空名单。任务选择继续沿用下线过滤、正名去重、适配策略检查和已有任务映射复用。

这部分前后两轮合计修改 10 个文件，最终 112 项相关测试通过，无失败、无跳过。修复已回写 `.2.2`；本会话尚未为这些技能改动提交或推送 Git。
