# 新增 API 的存在性与别名判定

文档索引提供候选名称。处理本库首次遇到的名称时，存在性以本批 PyTorch wheel 的核验结果为准，别名关系以本批对象比较结果为准。文档正文中的“已停用”“将移除”“某 API 的别名”等措辞，不单独触发下线、别名合并或关闭适配任务。

| 核验结果 | 首次登记时的处理 |
|---|---|
| wheel 中确认存在 | 按现行流程登记这个新增名称，再核对正名指向。正文即使写着“已停用”，也不能据此判为 wheel 中缺失。 |
| wheel 中确认不存在 | 暂缓登记，保留本轮核验记录。后续批次确认存在时再计入新增。 |
| 导入或依赖异常，无法完成核验 | 记录核验失败，待复核。不能据此判定缺失。 |

本流程所说的“两个入口 `==`”，指两个名称在同一 wheel 中解析到同一个 Python 对象。现行 Step 2.1 在同一进程中保留对象引用，用 `id()` 建立索引、用 `is` 确认身份。确认同一对象后按既有规则填写 `API真正名字`；只得到相同的值、相同的运行结果或文档中的别名描述，都不足以建立指向。普通布尔值和数值配置不参与对象判重。

例如，`torch.compiler.config.dynamic_shapes` 的文档写明它已停用。登记时仍以本批 wheel 对该名称的核验结果为准；它和另一个布尔配置的值同为 `True`，也不足以把两者合并。[Step 2.1 原流程](../steps/step2.1-api_prepare.md)
